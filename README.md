# منصة الخدمات الدراسية والطلابية (Academic Telegram Bot Platform)

منصة متطورة وقابلة للتوسع مبنية على معمارية Modular Monolith لتقديم 153 خدمة دراسية وأكاديمية متخصصة للطلاب والمدرسين والمؤسسات التعليمية عبر بوت تيليجرام تفاعلي وسريع الاستجابة.

---

## 1. المعمارية والمبادئ الهندسية

- **Modular Monolith:** تم تقسيم المشروع إلى 19 نطاق مجال (Domain Modules) مستقل بمسؤوليات واضحة وعقود برمجية محددة تحت `src/app/modules/`.
- **Database-First Consistency:** قاعدة بيانات PostgreSQL 18.x تحت مخطط `student_platform` تضم 128 جدولاً مع قيود سلامة صارمة وفهارس جزئية ومحفزات (Triggers) تضمن اتساق الحسابات والأسعار ومنع التضارب.
- **Transactional Outbox Pattern:** عزل معالجة المهام الطويلة والمهام المتزامنة والتكامل مع تيليجرام عبر جدول Outbox لتفادي حظر حلقة الأحداث (Event Loop) وضمان معالجة الأحداث لمرة واحدة على الأقل (At-least-once).
- **Graceful Redis Degradation:** إمكانية تشغيل النظام بالكامل سواء مع تفعيل Redis أو تعطيله عبر متغير بيئة موحد `REDIS_ENABLED=false` دون أي تعطل أو فقدان لوظائف الكتالوج والطلبات والمدفوعات.
- **Strict Academic Integrity:** فلتر ذكي استباقي لفحص استفسارات ومستندات الطلاب ومنع الغش المباشر وحل الاختبارات الحية، مع توجيه الطالب للشرح المفاهيمي.

## 2. حزمة التقنيات (Tech Stack)

- **اللغة:** Python 3.11
- **مدير الحزم والبيئة:** `uv`
- **إطار البوت:** `aiogram 3.x` (مع FSM و Routers وميدلوير مخصص)
- **قاعدة البيانات:** PostgreSQL 18.x (مع `asyncpg` و SQLAlchemy 2.0 Async ORM)
- **إدارة الترحيلات:** Alembic
- **التخزين المؤقت:** Redis (اختياري عبر `REDIS_ENABLED`) أو ذاكرة محلية في وضع التطوير
- **الإعدادات والتحقق:** Pydantic v2 و Pydantic Settings
- **الاختبارات:** pytest, pytest-asyncio, pytest-mock

## 4. الإعداد والتشغيل السريع

### المتطلبات الأساسية
- Python 3.11 مثبت
- مدير الحزم `uv`
- قاعدة بيانات PostgreSQL 18.x

### الخطوة 1: تثبيت الاعتماديات
```bash
uv sync
```

### الخطوة 2: ضبط متغيرات البيئة
انسخ ملف الإعدادات النموذجي:
```bash
cp .env.example .env
```
قم بتعديل متغيرات الاتصال بقاعدة البيانات في `.env`:
```ini
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DB=academic
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_password
REDIS_ENABLED=false
TELEGRAM_BOT_TOKEN=your_bot_token_here
```

### الخطوة 3: إنشاء المخطط وتطبيق الترحيلات
```bash
# إنشاء المخطط الأولي من database.sql
psql -U postgres -d academic -f database.sql

# أو تطبيق ترحيلات Alembic
uv run alembic upgrade head
```

### الخطوة 4: التحقق من جاهزية النظام
شغّل الأداة التشخيصية للتأكد من اتصال قاعدة البيانات وصحة الإعدادات:
```bash
uv run python scripts/check_system.py
```

### الخطوة 5: بذر بيانات الكتالوج التجريبي
```bash
uv run python scripts/seed_sample_catalog.py
```

## 5. تشغيل الاختبارات المؤتمتة

يحتوي المشروع على حزمة اختبارات شاملة تم التحقق منها بنجاح:
```bash
uv run pytest -v
```

تشمل الاختبارات:
- **Unit Tests:** فحص تشفير الأسرار في السجلات، وإعدادات البيئة، ومرونة الكاش، وفلاتر النزاهة الأكاديمية.
- **Integration Tests:** دورة حياة إنشاء الطلبات، وتطبيق التريجرات التلقائية لحساب الإجمالي، وعمليات الدفع بالنجوم، وجلسات التركيز وبطاقات المراجعة.
- **Security Tests:** التحقق من صلاحيات الأدوار (RBAC) ومنع التجاوزات الأمنية.
- **Flow Tests:** محاكاة مسار طالب كامل من التسجيل واستكشاف الكتالوج وحتى الدفع والتسليم.
- **Performance Tests:** اختبار ضغط العمليات المتزامنة وتفادي Race Conditions.

## 7. الأمان وحماية البيانات

1. **إخفاء الأسرار:** نظام Logging مزود بـ `SecretMaskingFilter` تلقائي يحجب مفاتيح API، وتوكنات البوت، وكلمات المرور في سجلات الكونسول والملفات.
2. **التحقق في قاعدة البيانات:** محفزات وقيود PostgreSQL تمنع اعتماد مبالغ غير متطابقة أو تعديل بنود الطلبات بعد دفعها.
3. **عزل الصلاحيات:** فحص الصلاحيات مبني على مستوى الخدمة ومستوى البوت، بحيث لا يكفي إخفاء الأزرار لمنع الإجراءات الحساسة.
